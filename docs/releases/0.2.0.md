# Serenity UI 0.2.0 — Developer integration

Date: 2026-11-23

This release strengthens integration contracts in the React kit and provides an executable HTTP reference application. The library remains backend-independent and MIT licensed.

## Added

- Checkbox native input refs, including React 19 callback cleanup, without losing indeterminate state or form semantics.
- DatePicker and TimePicker `triggerProps` for visible-button refs, focus/blur handlers and consumer styling.
- Optional `@serenity-ui/react/styles-no-preflight.css` for applications that supply their own compatible base reset.
- A real HTTP reference app with server field validation, error focus, remote table sorting/filtering/pagination, request cancellation and dashboard save/reload with conflict detection.
- Packed-consumer server rendering and browser hydration verification, plus a separate desktop/mobile integration job in GitHub Actions.
- An application integration guide, public form-contract table and Phase 14 development record.

## Fixed

- Select trigger refs now use stable composition and correctly clean up internal and consumer refs.
- Documentation now distinguishes checked/indeterminate state, native form refs, visible picker triggers and backend responsibilities.

## Upgrade

Existing component APIs and `styles.css` imports remain compatible. To avoid a second global Tailwind reset, replace the stylesheet import with `styles-no-preflight.css`; do not import both. The optional entry still shares utility names and tokens and requires a compatible application-owned reset.

React 19 remains the supported adapter. The package is distributed as source and a locally buildable archive; this GitHub release does not publish to npm. Run `npm run pack:local` to create `serenity-ui-react-0.2.0.tgz`, or `npm run example:integration` to explore the reference application.

## Validation and boundaries

See [Phase 14](../phases/14-developer-integration.md) for the actual verification record. The release is gated on GitHub Actions for its exact commit. The packed consumer checks representative SSR/hydration, not every framework or component combination.

The reference HTTP service stores data in memory and has no production identity or authorization service. Durable storage, sessions, ownership checks and deployment remain application responsibilities. Other framework adapters and comprehensive assistive-technology/browser certification remain future work.
